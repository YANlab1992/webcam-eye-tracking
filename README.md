# NeuroGaze Lab

基于本地 `webgazer.js` 的浏览器摄像头眼动研究演示。当前版本把 WebGazer 的九点回归预测作为正式坐标源，并加入独立验证、数据质量门控和恒速目标追踪。

## 在线体验 (GitHub Pages)

🌐 **在线运行地址**：[https://yanlab1992.github.io/webcam-eye-tracking/](https://yanlab1992.github.io/webcam-eye-tracking/)

> **提示**：浏览器摄像头 API（`getUserMedia`）在 Web 规范中强制要求安全上下文（HTTPS 或 `localhost`）。通过上述 GitHub Pages 链接可直接获得标准的 HTTPS 保护，被试或研究人员可直接通过现代浏览器（Chrome / Edge / Firefox 等）即开即用，无需配置本地环境。

## 本地运行

若需要在无网络环境下本地运行，摄像头 API 同样需要 `localhost` 或 HTTPS 服务（请勿直接双击 file:// 打开）。可使用 Python 启动本地微型服务器：

```powershell
python -m http.server 8765 --bind 127.0.0.1
```

启动后在浏览器中访问：`http://127.0.0.1:8765/`

## 推荐实验流程

1. 保持环境光稳定，避免面部背光；摄像头尽量与眼睛同高。
2. 输入实际视距和屏幕对角线。角度换算依赖这两个参数。
3. 选择“9 点校准 + 独立验证”。按高亮顺序注视并单击每个点一次，采样期间保持注视。
4. 完成 5 个非训练位置的独立验证。中位准确度描述系统偏差，RMS-S2S 描述逐样本精密度，有效采样率反映可用数据比例。
   如果系统发现各验证点存在方向一致的固定偏移，会自动施加 X/Y 屏幕偏置校正，并要求再次验证。
5. 正式比较时保持“研究评估（恒速目标）”。另外两个模式仅供互动练习，不能与研究评估数据混合比较。
6. 每个被试采用相同屏幕、浏览器缩放、视距、光照和任务顺序；条件允许时应随机或平衡任务顺序。

## 指标说明

- `Target_RMSE`：每个时刻注视点与同一时刻目标点的均方根距离，是正式追随任务的主要空间误差。
- `Median_Error` / `P95_Error`：稳健中心误差与尾部误差。
- `Valid_Sample_Pct`：通过面部居中、双眼睁开、预测新鲜度和场内范围检查的样本比例。
- `Coverage_Pct`：目标路径上有有效注视样本覆盖的比例。
- `Estimated_Lag_ms`：通过有限时移搜索得到的探索性追随延迟；眼动幅度不足或时移没有明显改善时输出空值。
- `Quality_Index`：扣除本次独立验证基线后，结合有效率和覆盖率形成的内部质量指数。它不是百分位、智力/注意能力分数或临床常模。

CSV 同时导出目标坐标、视线坐标、同步目标误差、路径误差、眨眼/头位质量标记，便于在 R、Python、JASP 或 SPSS 中重新分析。

若注视屏幕中心时红点仍出现稳定偏离，请保持注视中心约 1 秒后按空格键。“看中心对齐”会根据最近有效 WebGazer 原始预测的中位数计算持续偏置，不再只是临时移动红点。CSV/JSON 会记录原始预测与实际应用的 `Correction_X/Y`，便于排查。

## 解释边界

普通摄像头眼动受光照、眼镜反光、睫毛遮挡、头动、摄像头帧率和 WebGazer 模型误差影响。该程序适合教学、可行性研究和粗粒度轨迹/区域分析，不应替代实验室级红外眼动仪，不用于诊断神经、眼科或心理疾病。若用于论文研究，应预注册剔除标准、报告独立验证误差与有效采样率，并用目标人群数据评估信度和效度。
